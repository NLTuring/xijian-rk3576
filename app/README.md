# 息间 · 患者应用

已确认的黑白、圆润、玻璃按钮方案的第一版可运行实现。所有监测默认单人睡眠。当前交付为 **React + TypeScript 手机优先 Web/PWA 应用**，可在桌面调试、手机浏览器使用及添加至主屏幕；尚未打包 Android APK / iOS 原生安装包。

## 本地启动

需要 Node.js 22.12+（本次使用 24.18）及 npm。

```powershell
cd app
npm ci
npm run dev
```

打开终端显示的本机地址（默认 http://127.0.0.1:5188）。首次打开为示例体验，30 个夜晚都是固定的合成数据；可在“我的”切换至真实采集。

```powershell
npm run build          # 类型检查 + 生产构建，输出 dist
npm run preview        # 查看生产构建、测试 PWA 安装
npm test               # 核心逻辑测试
npm run test:coverage  # 核心领域与服务层覆盖率门槛 80%
npm run test:e2e       # 真实 Chrome 浏览器交互测试
```

E2E 默认使用系统已安装的 Chrome。没有 Chrome 时安装 Chromium，并在 `playwright.config.ts` 移除 `channel: 'chrome'`。浏览器测试使用虚拟麦克风，不录制周围真实声音。

### 真实收音的范围

- 当前用于验证手机前台收音，单次最长 5 分钟。页面进入后台时暂停。
- 采集到的声音真实保存；没有运行咳嗽/喘息识别，真实记录始终显示“待分析”。有效时长也需模型或质量规则确定，不以录音时长冒充有效监测时长。
- 没有实现整夜锁屏录音、设备连续传输或 RK3576 模型推理。目录中没有模型、权重或现成板端 API；[设备协议](docs/device-api.md) 定义当前健康检查契约。
- 完整夜间能力需要 Android/iOS 原生音频服务、麦克风中断恢复、板端协议与模型联调，以及真机长时验证。
- HTTPS 或本机 localhost 才能申请麦克风权限。普通局域网 HTTP 地址可看界面，但不能作为手机录音环境。

### 示例与真实记录

示例数据和真实记录按模式隔离显示，切换不删除数据。示例片段使用明确标注的**中性合成试听音**，不冒充真实咳嗽或喘息录音。反馈保留原始统计，不自动训练模型或改写诊断。

### 数据与隐私

- 不接入云端、不收集分析埋点；用户主动“检查连接”时只访问填写的局域网设备。
- 数据与声音使用 AES-GCM 保存于当前源的 IndexedDB，密钥不可导出，存于相同数据库。该方式不能防范同源恶意脚本或已解锁设备。
- 普通真实声音按 7/30/90 天保留期限在应用打开或修改期限时清理；收藏事件单独保留。摘要和笔记保留到用户主动清除。
- 浏览器清理网站数据、更换浏览器/设备/源地址后，不会自动迁移记录。PDF 下载到用户选择的位置，清除应用数据不会删除已下载文件。
- 正式保存敏感医疗数据前，需继续完善原生安全存储、访问控制及设备通信鉴权。

## 代码结构

```text
src/
  components/   玻璃按钮、对话框、时间轴、趋势图、记录表单
  pages/        今天、趋势、报告、我的、声音详情、睡前采集
  hooks/        加密状态加载与顺序保存
  domain/       类型、示例数据、统计规则
  services/     音频采集、存储、保留规则、设备连接、PDF、试听音
  App.tsx       导航和流程编排
  styles.css    黑白灰视觉与手机/桌面响应式布局
e2e/            浏览器流程与截图验证
docs/           设备接口与实机截图
```

PDF 以本地字体绘制到高分辨率 Canvas 后写入文档，保证离线中文可读；文字目前不可搜索。不依赖远程字体或图片。
